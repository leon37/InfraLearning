## AI Infra 项目经历

### 基于 Kubernetes 的分布式训练平台：gang 调度、配额准入与抢占
个人项目｜2026.03 - 至今

把用户提交的 TrainJob 跑成多 Pod DDP 训练。gang 调度、配额准入、抢占这几块自己实现，没有用 Volcano/Kueue，调度逻辑写在 kube-scheduler 插件里。

- **Gang 调度**：worker Pod 走自定义 scheduler，在 Permit 扩展点把先到的 worker 挂起，等同组凑齐 minMember 再一起放行。凑不齐时，靠 PodGroup 上的 round 计数 + Permit 超时 + Unreserve 级联做有界重试和整组回收，避免只调度了一半、占着资源又起不来。round 自增放在调度周期里做，利用调度周期串行的特性省掉加锁。
- **配额准入**：单独的 Queue CRD，由 controller 按优先级判断配额、决定放行哪个 TrainJob，准入通过才创建 Pod。配额判断和物理调度分在两处，不会先创建一堆调度不了的 Pod 堆在调度器里。
- **抢占**：高优先级组资源不够时，PostFilter 里挑一个优先级更低、驱逐后能腾出足够空间的组作为 victim，算出抢占后每个节点能放几个 worker、存回 PodGroup。驱逐是在 victim 的 PodGroup 上写标记、让 victim 自己的 controller 去删 Pod，不从 scheduler 直接删（直接删 controller 会立刻重建）。抢占方下一轮调度在 PreFilter 读回计划、Filter 只允许它落在预留节点。victim 通过字段索引找到、按抢占方状态回到排队。
- **TrainJob 与 DDP**：TrainJob CRD 按 worldSize 展开 worker，注入 RANK / WORLD_SIZE / MASTER_ADDR，rank0 用 ClusterIP Service 做 rendezvous 入口。PyTorch DDP 在 kind + Gloo 下验证多 rank 起训、process group 初始化、rank0 写 checkpoint 到 PVC，用 attempt label 区分重试轮次。
- **验证**：复现过高优组抢占低优组的完整过程——victim 被删、抢占方按计划落到预留节点跑起来、victim 释放后重新排队。环境是 kind，2 个 worker 节点。
- **当前边界**：抢占只处理 CPU、一次只驱逐一个组、没有跨队列回收、也没做防止第三方在空隙里偷占资源（标准做法是 NominatedNodeName 预留）；跑在 kind + CPU/Gloo，不是真实 GPU/NCCL/RDMA。

技术栈：Go、controller-runtime、Kubernetes Scheduler Framework、CRD/Informer 字段索引、Kind、PyTorch DDP/Gloo、PVC。
