### 一、Go 与系统底层

| 知识点 | 评级 | 上次 | 下次 | 要能说出来的那句 | 卡点 |
|---|---|---|---|---|---|
| GMP：goroutine 阻塞在 channel 时发生什么 | **C** | 08-13 | 08-17 | 用户态阻塞 → gopark，G 从 `_Grunning` 变 `_Gwaiting`、从 M 上摘下来挂到那个 channel 的 recvq；**M 一点没阻塞**，立刻拿下一个 G 跑。系统调用阻塞则不同：M 真被卡住，runtime 把 P 解绑交给别的 M（handoff）——**这才是 P 存在的核心价值** | 模拟面完全答不出，只说了"因为有 GMP 模型嘛"。**名词填空是最伤的答法** |
| channel 的 hchan 结构 | B | 08-14 | 08-21 | 每个 channel 自己带 `recvq`/`sendq` 两个等待队列 + 环形缓冲 `buf` + 一把锁。**等待者挂在 channel 身上，才能让对端 O(1) 找到并直接交付**。channel 操作本身是加锁的 | — |
| cgroup 怎么限制 CPU | **C** | 08-13 | 08-17 | **打卡计时**：每 100ms 发一张工时卡，卡上写这周期最多能用多少毫秒（限 2 核 = 200ms）。用光就**让你停下来等**下个周期。**它让你等，不杀你——这就是"可压缩"** | 第一次讲堆了 CFS/配额桶/nr_throttled 一堆术语，听不懂；换成打卡比喻才通 |
| cgroup 怎么限制内存 | C | 08-14 | 08-17 | **记账**：每次申请内存记一笔，超上限先回收（刷缓存），回收不动就 **OOM 杀进程**。**没有"等一会儿"这个选项，所以不可压缩** | — |
| `limits.cpu: 2` 到内核的完整链路 | **C** | 08-13 | 08-17 | yaml → apiserver → kubelet → **CRI** → containerd → shim → **runc 写 cgroup 文件**。落成 `cpu.cfs_period_us=100000` + `cpu.cfs_quota_us=200000`。requests 落成 `cpu.shares`（相对权重，不是上限）。**runc 干完就退出，容器的父进程是 shim，所以 containerd 重启不杀容器** | 模拟面答"不知道，工作中很少实操 docker" |
| 容器的本质 | B | 08-13 | 08-21 | 不是虚拟机，**就是宿主机上一个普通进程**，被三样东西修饰：**namespace 换视图、cgroup 卡资源、rootfs 换根**。和宿主机共用同一个内核 | — |
| overlayfs / 镜像分层 | B | 08-13 | 08-21 | 镜像是只读层叠起来，运行时加一个可写层，overlayfs 合并成一个视图（lowerdir/upperdir/merged）。**写时复制**——改只读层的文件要先整个复制到可写层，所以往容器里写大文件慢。删除是打 whiteout 标记遮住，**下层文件还在，所以镜像里删掉的密钥能被翻出来** | — |
| GOMAXPROCS 在容器里的陷阱 | B | 08-13 | 08-21 | Go 默认取宿主机核数、**不认 cgroup**。容器限 2 核跑在 64 核机器上 → 开 64 个 P → **十几毫秒烧光 100ms 的配额 → 剩下八十多毫秒整组停摆**，表现是 CPU 用不满但延迟毛刺、`nr_throttled` 暴涨。根子是 **procfs 没被容器化**，`/proc/cpuinfo` 读到的是宿主机的。解法：显式设或用 `automaxprocs` 读 cgroup 算 | — |
| NUMA | B | 08-14 | 08-21 | 一台机器多颗 CPU，**每颗有自己直连的内存**。读自己的快，读隔壁的要过 CPU 间总线、延迟 1.5~2 倍。**一个 NUMA node = 一颗 CPU + 它的内存 + 挂它 PCIe 下的设备**。单位是"一颗 CPU"不是"一个核"——消费级单路机器是 UMA，没这问题 | — |
| CPU↔GPU 的数据通路 | B | 08-14 | 08-21 | CPU **能**直接寻址显存（PCIe BAR），但**每次访问一个 PCIe 事务且不可缓存**，只用来读写控制信息。搬数据走 **DMA**，源必须是主机的**锁定内存**（DMA 认物理地址）——`pin_memory=True` 就是干这个。所以路径是 **锁定内存 → DMA 走 PCIe → 显存**，要不要绕 UPI 取决于内存和卡是否同 NUMA | — |
| GPU↔GPU 的数据通路 | B | 08-14 | 08-21 | 有 NVLink 就**卡对卡直连、不经过 CPU 和内存**；没有就 GPU→PCIe→主机内存→PCIe→GPU，慢好几倍，跨 socket 再多绕一趟。**多卡训练的 all_reduce、多卡推理的张量并行走的全是这条路** | — |

### 二、Kubernetes

| 知识点 | 评级 | 上次 | 下次 | 要能说出来的那句 | 卡点 |
|---|---|---|---|---|---|
| Service 是干什么的 | **C** | 08-14 | 08-17 | **Pod 的 IP 靠不住**（随时重建、IP 会变），Service 给一个永不变的名字和虚拟 IP。**在我项目里用的是第一件价值**：MASTER_ADDR 必须在创建 Pod 时就注入，但那时 rank0 的 IP 还不存在——**Service 的名字在 Pod 创建之前就确定了**，这是解开鸡生蛋的关键 | 自己项目里用了，但忘了它是干嘛的 |
| CoreDNS + kube-proxy：ClusterIP 怎么转发 | **C** | 08-13 | 08-17 | Pod 的 `/etc/resolv.conf` 指向 CoreDNS，解析出 **ClusterIP（虚拟 IP，不属于任何 Pod、ping 不通）**。转发靠 **kube-proxy 在每个节点写 iptables/IPVS 规则**，包命中 NAT 规则 **DNAT 成后端 Pod IP**。**kube-proxy 不在数据路径上，真正转发的是内核 netfilter** | 模拟面只答出"有个 DNS 服务，具体记不清" |
| Deployment / ReplicaSet | B | 08-14 | 08-21 | 跑常驻服务的标准对象。**内部两层：Deployment 管版本、ReplicaSet 管数量**。滚动更新 = 新建一个新版 ReplicaSet，新的调上去老的调下去；**老的不删只缩到 0，所以回滚极简单**。里面的 Pod 互相等价可替换——**这就是"副本"的定义，也是它跑不了训练的原因** | 之前完全没用过 |
| controller-runtime：Reconcile 什么时候再来 | **C** | 08-13 | 08-17 | **默认不会再来。** `ctrl.Result{}, nil` = 处理完了别再叫我。三条路让它再来：**新事件**、**`RequeueAfter`（唯一的"定时"，逐次显式声明）**、**返回 error 走限速队列指数退避**。informer 的 resync **默认 10 小时**，是防漂移的兜底、**绝不能当推进动力** | 模拟面答"应该有个定时器"——错，而且这个错在自己项目里有受害者（PreemptionDetail 清不掉那个疑问） |
| requests vs limits / capacity vs allocatable | A | 08-13 | 09-03 | 调度器看 **requests**。allocatable = capacity − 系统预留（kubelet、OS、驱逐阈值） | 答对了 |
| Device Plugin | B | 08-13 | 08-21 | DaemonSet 向 kubelet 注册 → kubelet 把 `nvidia.com/gpu: 8` 写进 node 的 capacity/allocatable → 调度器从 NodeInfo 看到。**给调度器的只是一个计数**，设备属性和拓扑没地方放 | — |
| Topology Manager 四档策略 | **C** | 08-14 | 08-17 | 作用在**分配的第二步**（调度器选节点是第一步，kubelet 选具体哪几个核/哪张卡是第二步）。协调 CPU/Memory/Device Manager 别各分各的。四档：`none`不管 / `best-effort`对不齐也跑 / `restricted`对不齐就拒（但允许"跨node本就最优"）/ `single-numa-node`必须单node。**三个硬伤：只有 NUMA 一个维度、调度器完全不知情（导致 TopologyAffinityError 死循环）、策略是节点级不是 Pod 级** | 完全忘了有哪四档 |
| DRA | B | 08-14 | 08-21 | **把设备从"一个计数"变成"能描述属性的对象"，让调度器在选节点时就参与匹配。跟 hostPath→PVC 是同一个转变。** ResourceSlice(≈PV) / DeviceClass(≈StorageClass) / ResourceClaim(≈PVC)。**杀手能力是跨设备约束**——"给我 4 个设备，它们的 nvlinkDomain 必须是同一个值" | 版本号别硬报 |
| PVC 的 RWO / RWX | B | 08-13 | 08-21 | **Once/Many 指的是节点数，不是 Pod 数**。同节点多个 Pod 可以共用 RWO。块存储（云盘、local-path）基本只能 RWO——**两台机器同时挂载写会把文件系统元数据搞坏**；文件存储（NFS/CephFS）支持 RWX，并发在服务端统一处理 | — |

### 三、推理侧

| 知识点 | 评级 | 上次 | 下次 | 要能说出来的那句 | 卡点 |
|---|---|---|---|---|---|
| KV Cache | B | 08-14 | 08-21 | 每写一个新字都要回看前面所有字；前面那些字的 K/V 算完**永远不变**（后面的字影响不到它们），所以缓存。**7B 模型：权重 14GB，50 个并发对话的 KV Cache 约 50GB——缓存比模型大三倍，而且运行时才产生**。→ **推理的显存需求写不死在 requests 里，这是推理调度比训练难的根源** | 复述基本完整，漏了 Query 那一环 |
| PagedAttention | B | 08-14 | 08-21 | 传统按最坏情况预留连续显存 → **预留浪费 + 碎片**，利用率只有二三十。解法是**把操作系统的分页搬进显存**：固定大小块、按需领、不要求连续、块表记位置。利用率提到 90%+。**这是 vLLM 的核心。** 附带能力：相同前缀共享块（COW） | 复述准确 |
| continuous batching | B | 08-14 | 08-21 | 传统凑批**必须等最慢的那个算完整批才返回**，短请求被长请求拖死。continuous batching = **谁生成完就放走、马上补新的进来**。**能这么干正是因为 PagedAttention 按块管显存，才能随时踢掉一个塞进一个**——两者配套 | — |
| vLLM / TGI / TensorRT-LLM | B | 08-14 | 08-21 | vLLM 事实标准；TGI 是 HF 生态的；**TensorRT-LLM 是编译型，性能天花板但产物跟 GPU 型号绑死——所以在异构集群里它是一条硬亲和约束**（引擎选型直接影响调度策略） | — |
| KServe | B | 08-14 | 08-21 | 把"部署一个模型"声明化那一层。一个 InferenceService 展开成 **Deployment + Service + HPA + 路由**，**跟我写 TrainJob controller 是一模一样的模式**。多做三件事：模型加载（storageUri + initContainer）、挑引擎（ServingRuntime）、灰度（canaryTrafficPercent）。**大模型一律用 RawDeployment 而不是 Serverless——几十G权重加载要几分钟，缩到零不现实** | 第一次讲太抽象，看 YAML 才懂 |
| 副本的三种形态 / LWS | B | 08-14 | 08-21 | ①单卡副本 1Pod ②**单机多卡副本仍是 1 Pod**（张量并行在 Pod 内部）③多机多卡副本 = 多个 Pod。**只有第三种 Deployment 表达不了**（replicas 是互相独立的 Pod，没有"一组 Pod 算一个副本"的概念）→ 这就是 **LeaderWorkerSet** 存在的理由 | 这条是自己抓出我描述里的简化错误的 |
| 两层调度 | A | 08-14 | 09-04 | **K8s 调度器**决定 Pod 落哪台机器哪张卡（秒~分钟）；**引擎内部调度器**决定这一毫秒哪几个请求凑一批（毫秒）。互不干涉，但上层决策质量直接决定下层能榨出多少吞吐 | — |

## 元趋势跟踪

> 仿算法台账的做法，记跨知识点的模式，比单条更重要。

- **2026-08-14**：三场面试暴露的**共同失败模式不是不知道，是"知道但讲不出"**。五次答不出里有四次是「几个月前学过、没复习、想不起细节」。→ **这个台账就是针对这一条建的。**
- **2026-08-14**：答不出时的归因方式有问题——说了五次"我忘了 / 工作中很少实操"，**这是把问题归到"我没掌握"**。正确做法是**给出还记得的骨架**（"这块我之前专门看过，最近没实际用到，细节想不起来，我还记得的是……"）。**空白 和 "记得框架忘了细节" 在面试官那里差一个档次。**
- **2026-08-14**：最伤的一种答法是**用名词填空**（"因为有 GMP 模型嘛"）。宁可说"这块我说不上来"。
