# 面试开场白 — 护城河项目（mini Kueue + mini Volcano）

> 用途：回答"简单介绍一下你这个项目"。口播约 2.5 分钟。
> 首次使用：2026-08-13 同花顺「AI 基础设施」岗一面。
> 原则：不背稿，背的是五格结构和六个钩子；措辞可以临场变，结构不能丢。

---

## 口播稿

这个项目是我自己写的一个批量训练作业的调度平台 demo。

做它的起因是分布式训练的一个硬约束——DDP 训练里，多个 worker 要先会合、建立通信域才能开始，之后每一步反向传播都要做一次 all_reduce 同步梯度，全员到齐才能进下一步。所以它是 all-or-nothing 的：8 个 worker 起来 7 个，不是慢一点，是那 7 个占着资源死等，一步都跑不了。而原生的 Job 加默认调度器给不了这个语义——调度器的最小调度单位是 Pod，它会很乐意把能放的先放下去、剩下的挂 Pending，正好制造出那个死等的局面。

所以我把它拆成了两层。

上面是控制器层。TrainJob 是作业本身的 CRD，有自己的状态机；QueueController 负责配额准入，在作业进调度之前先算队列额度够不够，不够就卡在 Queued，**连 Pod 都不创建**；PodGroup 是调度器和控制器之间的契约对象，两边靠它解耦。

下面是调度器层。我扩展的是 kube-scheduler 的调度框架，写插件打包成一个自定义调度器——**这里说清楚，我不是自己写了一个调度引擎，是在 kube-scheduler 的扩展点上做的**。gang 落在 Permit：先到的 worker 在这儿被扣住，凑齐 minMember 才整组放行去 bind；凑不齐就超时整组 Deny、级联 Unreserve 把半组拆掉，不占着资源不放。抢占落在 PostFilter：资源不够时挑低优先级的作业驱逐，而且是按整组算的，不是按单个 Pod。

这套设计里有一个我觉得挺有意思的张力：配额准入在控制器层，物理调度在调度器层，**这两层是异步的——准入通过不代表物理上装得下**。我自己跑实验的时候就撞到过：一个高优先级作业配额过了、Pod 也建出来了，但节点上的 CPU 就是拼不出来。所以抢占在我这套设计里不是一个额外功能，而是**兜住这两层不一致的必需品**。这也是 Kueue 式分层要付的代价，换来的是调度器保持简单、不会堆一堆永远调度不上的 Pod。

范围上我说明一下：这个 demo 只做了 CPU 单一资源，没有多资源公平算法；端到端是在 kind 集群上用 CPU 和 Gloo 后端验的，没有真实 GPU 和 NCCL 环境。

## 五格结构（真正要背的东西）

| 格 | 内容 | 作用 |
|---|---|---|
| 1 | 它是什么 | 一句话定位 |
| 2 | **为什么需要它** | all_reduce 全员到齐 → all-or-nothing → 原生 Job 给不了。**没有这格，后面所有设计都失去坐标系** |
| 3 | 做了哪两层 | 控制器层（CRD/准入）+ 调度器层（Permit/PostFilter），各自落在哪个扩展点 |
| 4 | **设计张力** | 两层异步 → 准入 ≠ 装得下 → 抢占是必需品。**唯一能证明"真想过"的一格** |
| 5 | 边界 | 说成范围声明，不是认罪清单 |

第 2 格和第 4 格是全段的重心，其余可压缩。

## 埋进去的六个钩子（面试官大概率顺着问）

每一条后面的展开在 2026-08-11 的模拟面里都过过一遍：

1. **"all_reduce 全员到齐"** → 引向 DDP 通信机制。素材：DDPLab 里跑过 Gloo 后端，观察过通信在单步耗时里的占比；边界诚实划在 CPU/Gloo。
2. **"连 Pod 都不创建"** → 引向 Kueue 式 vs Volcano 式配额分层的取舍。买到：调度器简单 + 不堆无效 Pod + 分层干净；代价：准入 ≠ 装得下、配额粗看不到节点级装箱、无跨队列借用/reclaim。
3. **"不是自研调度引擎"** → 主动拆掉"过度声称"这颗雷。对照：Volcano 是自研引擎（Session + Action，批量看一堆 PodGroup），我是逐 Pod 进框架，所以只能用 Permit 等待室凑。
4. **"凑不齐超时整组 Deny"** → 引向轮次时钟全链：进等待室 → Permit 超时 → Deny → Unreserve 级联清场 → 等待数归零 → 下一轮 round+1 → 到 scheduleMaxLimit 认输。
5. **"抢占是必需品"（主钩子）** → 引向抢占全链，以及三个已知缺口：无多 victim 组合、无 NominatedNodeName 防偷（后果是优先级倒挂 + victim 白驱逐）、victim 选择只按优先级不算代价。
6. **"只做了 CPU"** → 引向 GPU/NPU 迁移。接入路径走 kubelet 的 Device Plugin（上报成 extended resource，Filter 基本不用改）；差异在整卡不可压缩、碎片致命、抢占代价从"重启进程"变成"烧机时"；缺 DRF、拓扑感知、显存共享。

## 念稿提示

- **不要说"基于 Volcano 和 Kueue 的处理逻辑写的"**——会被听成照着实现抄。真实经历是先自己设计实现、事后对照才发现分层撞上了，后者含金量高得多，而且不怕追问"Volcano 的 session/action 你怎么借鉴的"。
- **不要说"CRD 完成了配额准入"**——CRD 只是数据载体，做准入的是 QueueController。这是反复犯的口头习惯（2026-08-11 一晚犯两次）。
- **不要说"所有 Pod Running 之后 job 就 Running"**——跳过了 Permit 凑齐 Allow → bind 这道招牌屏障。Permit 放行的是去 bind，Running 是 kubelet 起容器之后的事。
- **谁改谁的状态要分清**：scheduler 只碰 PodGroup，controller 才碰 TrainJob 的 phase。QueueController 只写 `queue.Status.Used`，翻 Starting 的是 TrainJobController。
- **NominatedNodeName 那条缺口不要放进开场**——太具体，等于主动递刀。等被问到抢占再拿出来，那时它是"我知道自己缺口在哪"。
